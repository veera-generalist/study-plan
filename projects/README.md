# Portfolio project briefs

Build these incrementally in your own project directory or repositories. These are specifications and acceptance criteria, not claims that the finished applications are bundled here.

These optional briefs retain the earlier QA domain. You can instead extend the Maple Books project from [Lesson 12](../modules/12-optimization-and-career.md), applying the same engineering and evaluation criteria to shop documents and return-request drafts. Choose a domain you want to investigate; QA knowledge is not a prerequisite for the beginner course.

1. [Bug-triage evaluation](01-bug-triage.md)
2. [QA knowledge assistant](02-qa-knowledge-assistant.md)
3. [Tool-using QA workflow](03-tool-using-workflow.md)
4. [Evaluation and release pipeline](04-evaluation-pipeline.md)

For each project, publish a problem statement, architecture, setup, data provenance, baseline, evaluated change, reviewed failures, limitations, and evidence-backed recommendation. Use synthetic/publicly reusable data and link sources.

## Shared capstone rubric

| Dimension | Evidence expected |
|---|---|
| Engineering | Small interfaces, explicit errors, bounded execution, reproducible setup |
| Dataset | Clear sampling, provenance, labeling, splits, and limitations |
| Evaluation | Suitable graders, error policy, slice results, reviewed failures |
| Experiment | Preserved baseline, paired comparison, uncertainty assumptions |
| Operations | Useful traces, latency/cost evidence, deployment criteria |
| Communication | Honest claims, source credits, concise demonstration |

Meeting this rubric demonstrates project learning. It does not establish production readiness for every deployment.
