# How to use the first three lessons

## Start with one lesson

Open [Lesson 01](modules/01-python-engineering.md). You do not need to install software or learn a list of technical terms before reading.

The first three lessons use a fictional business called Maple Books. The shop facts are deliberately short so you can check the examples yourself.

Each lesson follows the same pattern:

1. Read the introduction and learning objectives.
2. Follow the explanation and worked example.
3. Try the small activity.
4. Complete the assignment in your own words.
5. Attempt the knowledge check before opening the answers.

Take breaks between those steps. The aim is to understand the ideas, not finish a large amount of reading quickly.

## What you need

A notebook or a simple text document is enough to complete the written activities.

If you already use an AI chat tool, you can try the prompts there. That is optional for these lessons. The written replies in the lessons are teaching examples, not records of real model runs.

When you do try a tool, save what it actually says. A different response is something to examine, not automatically evidence that you did the exercise incorrectly.

## What to write down

Keep one short document with three parts:

| Lesson | Your note |
|---|---|
| 01 | The assistant you would like to build, who it helps, and how you would check an answer |
| 02 | Three questions, the replies you reviewed, and your observations |
| 03 | A starting prompt, one change, and what happened on different questions |

If you used supplied examples, label them as supplied examples. If you used a live tool, record the tool and date.

## How to judge your progress

You are ready to move on when you can explain the lesson's main idea in your own words and complete its activity with reasons.

For example, it is useful to say: “This reply invented Sunday opening hours, because the shop information says it is closed.” Repeating a definition without recognizing that mistake is less useful.

If a question is confusing, reread its worked example and try answering aloud. Use the glossary only for the word you need.

## Where Python fits

Python remains the implementation language for the coding part of the wider course. The current three lessons establish what the application should do before asking you to program it.

The old code-heavy first-three chapters are now optional [technical notes](advanced/README.md). You do not need to finish them before completing these introductory lessons.

## What happens after the third lesson

Review your three notes and identify what is still unclear. The later Modules 04–12 are the previous technical draft; they have not yet received this rewrite.

The wider roadmap and project briefs remain available for later. For now, completing three understandable lessons is the useful next step. There is no requirement to create a large dataset, compare paid services, or build a complete application at this stage.

## A workable solo-review path

Later lessons discuss comparing judgments from different reviewers. Reviewing the same answer twice yourself does not provide the same evidence as two independent reviewers. If you are studying alone, a delayed second pass with examples reordered can help you notice mistakes, but describe it as solo review. Keep the original decisions and note what changed. Cases that need specialist judgment can remain unresolved until you can obtain that review.
